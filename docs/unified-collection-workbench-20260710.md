# 单一采集工作台合并说明

## 背景

系统曾在同一个前端工程中提供“采集工作台”和“系统管理”两个独立外壳，并通过浏览器本地状态切换默认入口。这导致 `/` 与 `/?final=20260710` 在不同浏览器或不同本地状态下呈现出明显不同的能力集合，Worker、设备、有效 SKU、风险和原始产物等生产能力可能被隐藏。

## 当前决策

从 2026-07-10 起，Dashboard 只保留一个面向内部运营和管理人员的生产工作台：

- `/` 与 `/?final=20260710` 使用完全相同的入口和数据上下文。
- 不再读取或写入工作台模式的 `localStorage`。
- 不再展示“返回采集工作台”或“系统管理”切换按钮。
- 业务 ViewModel/API 继续保留，用于门店完成度、实时动态和业务文件交付。
- Worker、账号、Profile、CDP、风险干预、原始数据和审计能力继续保留在同一导航内。

## 统一导航

1. 作战：作战指挥大盘、门店采集进度、类目任务调度、实时采集进度。
2. 资源与风控：资源拓扑、账号识别、Profile/CDP。
3. 数据与审计：风控干预台、业务数据结果、原始数据资产、操作审计、门店与批次配置。

## 首页保留能力

- 今日目标门店与采集批次进度。
- Worker 在线/离线状态。
- 健康账号池与风险账号数量。
- 数据库中的有效 SKU、去重商品和真实到手价数量。
- 风险待处理、阻断任务、断联设备和原始产物归档。
- 生产就绪检查。
- 门店类目切片进度。
- 深色实时采集日志摘要，汇总 Worker、门店、类目、任务状态和已采商品数量。
- Worker 节点、账号、CDP 和当前采集切片速览。

## 数据和状态口径

- 有效 SKU 使用结构化商品快照汇总，不再简单累加任务计数。
- `completed_valid` 与 `completed` 计入完成。
- `assigned`、`running`、`collecting`、`captured`、`uploading`、`structuring`、`validating` 计入执行中。
- `manual_required`、`needs_review`、`failed` 计入阻断或待处理。
- 真实到手价仅展示已确认具有真实到手价语义的数据数量。

## 验证标准

- 两个 URL 均展示作战指挥大盘，且无工作台切换按钮。
- Worker 设备、有效 SKU、风险待处理和实时采集日志摘要同时可见。
- 所有导航页均可访问并保留原有操作能力。
- 桌面端和 390px 移动端无横向溢出。
- Dashboard 测试、类型检查和生产构建通过。
