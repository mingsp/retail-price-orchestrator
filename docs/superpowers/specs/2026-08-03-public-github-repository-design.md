# 商圈比价公开 GitHub 仓库设计

## 目标

在 `codewith1024` 组织下建立公开仓库 `retail-price-orchestrator`，持续发布商圈比价 Master-Worker 系统的代码、采集工具、生产策略、部署材料和新人指南。公开仓库必须能被新同事独立理解、安装、演练和持续更新，同时不暴露生产身份、凭据、路径和真实采集产物。

## 发布原则

1. **干净快照**：从当前工作树生成新的 Git 历史，不复制旧远端历史。
2. **源码完整**：保留 Master、Worker、Dashboard、CDP/Profile 管理、确定性采集器、断点恢复、风险闭环、原始数据审计、部署和交接工具。
3. **事实边界**：README 分开标注已实现、已离线验证、待现场验证，不用演练结果冒充生产验收。
4. **原始优先**：原始 JSONL/对象存储是事实源，下游 Excel、MySQL 和比价逻辑是可替换投影。
5. **秘密外置**：完整手机号、账号归属、Cookie、验证码、Webhook、Token、数据库和 SSH 凭据只存在包外私密配置。
6. **合规使用**：只支持授权账号、低频、人工介入和可暂停采集；不提供验证码绕过、指纹伪造、静态签名、账号或代理池规避方案。

## 仓库信息

- 仓库：`codewith1024/retail-price-orchestrator`
- 可见性：公开
- 许可证：MIT
- 项目说明：`面向即时零售竞对价格监控的 Master-Worker 数据采集调度系统，支持多设备、多账号、Profile/CDP 绑定、低频可恢复采集、人工验证、原始数据归档与质量验收。`
- GitHub Topics：`retail-tech`、`price-monitoring`、`master-worker`、`cdp`、`human-in-the-loop`、`typescript`
- 中文短标签：`采集`、`调度`、`风控`、`数据`、`部署`、`文档`、`缺陷`、`优化`

GitHub Topics 受平台限制只能使用小写英文字母、数字和连字符。中文短标签通过 README 徽章和 Issues Labels 呈现。

## 首页信息架构

README 的阅读顺序固定为：

1. 一句话说明系统解决什么问题。
2. 中文短标签和当前验证状态。
3. 合规边界与不包含内容。
4. Master-Worker 架构与一条完整数据链路。
5. 五分钟离线体验。
6. 新人从零采集入口。
7. 生产部署入口。
8. 403/418、验证码、Profile 污染和断点恢复入口。
9. 数据完整性与原始数据交付入口。
10. 开发、测试、发布和贡献方式。

`HANDOFF_START_HERE.md` 和 `START_WITH_THIS_PROMPT.md` 继续作为运营新人和新 Codex 的强制入口，不把全部操作细节堆进 README。

## 目录边界

- `apps/master/`：调度、租约、资源绑定、风险、质量和产物登记。
- `apps/worker/`：CDP 生命周期、任务执行、断点、上传和本地降级。
- `apps/dashboard/`：统一采集调度工作台。
- `packages/shared/`：Master/Worker 共享契约。
- `scripts/`：确定性采集、审计、自检和发布工具。
- `infra/`、`deploy/`：本地基础设施和生产部署。
- `docs/handoff/`：新人操作、风险处理、完整性验收和提示词。
- `examples/deidentified/`：少量脱敏样例，仅用于离线回放。
- `.github/`：CI、Issue 模板、PR 模板和维护配置。

公开仓库不包含 `.runtime/`、`profiles/`、`data/`、真实 JSONL/Excel、环境文件、发布临时目录和私密账号映射。

## 发布流水线

1. 使用白名单复制当前源码到独立 staging 目录。
2. 运行凭据、完整手机号、本机路径、真实 URL 参数和运行产物扫描。
3. 运行交接专项测试、工作区测试、类型检查和生产构建。
4. 在 staging 中初始化全新 Git 仓库并创建单一首发提交。
5. 创建 GitHub 公开仓库，设置说明、Topics、中文 Issues Labels 和功能开关。
6. 推送 `main`，创建 `v0.1.0` Release，并附验证摘要。
7. 从 GitHub 匿名 clone 到新目录，重新运行脱敏和上手验证。

## 维护方式

- `main` 只接收通过 CI 和脱敏扫描的变更。
- 功能、文档和风险策略均通过 PR 更新。
- 每次发布记录“新增能力、行为变化、迁移说明、验证证据、现场验证缺口”。
- 安全问题通过 `SECURITY.md` 指定的私密渠道报告，不在 Issue 中粘贴真实账号、链接参数或日志。
- 新策略先进入脱敏样例和测试，再进入生产手册；生产事故结论必须有证据，不凭经验猜测。

## 验收标准

- 匿名用户能访问仓库并从 README 找到安装、演练、生产和风险手册。
- 仓库描述、Topics、中文标签、许可证和默认分支正确。
- 脱敏扫描为零发现，Git 历史中不含旧提交。
- 所有必要源码、脚本和文档存在，内部链接有效。
- CI、类型检查、测试、生产构建和脱敏样例回放通过。
- 匿名 clone 后可完成离线 doctor，不需要生产凭据。
