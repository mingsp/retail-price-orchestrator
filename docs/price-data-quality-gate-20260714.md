# 价格数据质量门禁

## 目标

业务事实表只接收能够解释、能够追溯、价格语义一致的数据。来源异常值不删除，继续保存在原始 JSONL、对象存储及 PostgreSQL `raw` 字段中，但不得伪装成用户到手价进入业务比价。

## 价格语义

- `front_display_price_amount`：用户在商品列表或商品页直接看到的页面价格，包括 0.01 元限购引流价。
- `user_final_price_amount`：有明确来源路径且数值大于 0 的用户到手价。
- `original_price_amount`：原价或划线价，只用于折扣说明。
- 比较价属于比价脚本的运行结果，不写入 SPU/SKU 来源事实表。

## 强制阻断规则

1. 每条正常商品/SPU/SKU 都必须有 `front_display_price_amount`；页面展示价缺失一行即阻断。
2. 到手价是可选优惠字段，缺失不代表数据不完整，也不设置覆盖率放行阈值。
3. 到手价存在时必须是有限数字且大于 0，并且有原始来源证据。
4. `price_semantics='actual_payable'` 时必须同时存在来源路径和大于 0 的数值。
5. 无效到手价数量大于 0 时，批次禁止业务导出和 RetailMart 同步。
6. 商品名称、门店、类目、来源商品 ID、采集时间缺失时禁止同步。
7. 同一批次业务唯一键重复时禁止同步。

## 合法低价规则

- `0.01`、`0.05`、`0.10` 等大于 0 的页面活动价正常保留。
- 页面活动价必须结合 `promotion_text`、`limit_purchase_quantity`、`sale_status` 和原价解释。
- 首件限购价与普通售价分开比较，不得把一方限购引流价直接描述为长期价格优势。

## 零元异常处理

- 来源返回到手价 0，但页面展示价大于 0 且缺少明确免费条件时，将结构化到手价隔离为空。
- 比价脚本可按业务场景回退为页面展示价，数据库不固化该选择。
- 原始响应不修改，后续仍可按来源字段重新审计。
- 页面展示价本身为 0 的门店说明、福利入口等记录继续保留页面原值，由比价脚本排除。

## 防线

1. Worker 解析层：0 元到手价不生成结构化到手价字段。
2. PostgreSQL 质量层：统计无效到手价，存在异常时阻断批次。
3. 业务导出层：只导出大于 0 的有证据到手价。
4. RetailMart 同步层：再次拒绝小于等于 0 的到手价。
5. 验收层：检查总数、唯一键、关键字段、价格覆盖、异常价格和源端对账。
