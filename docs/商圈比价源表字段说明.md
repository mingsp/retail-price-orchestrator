# 商圈比价源表字段说明

## 一、表的用途

表名：`fact_store_raw_data_snapshot`

该表用于保存门店采集到的完整原始数据，是商圈比价的数据源表。

- 不在本表内计算比价结果。
- 不提前删除暂时不用的商品字段。
- 商品、SKU、价格、库存、规格和促销等原始信息完整保存在 `raw_data` 中。
- 后续 SPU、SKU 清洗及比价脚本都可以从本表重新取数。

## 二、数据粒度

本表一行代表一条商品观察记录或类目记录，不代表一个 SKU。

```text
一条商品记录
└── raw_data.productRaw
    └── skus[]：该商品包含的一个或多个 SKU
```

因此，不能用本表的商品行数直接代表 SKU 数量。需要展开 `raw_data.productRaw.skus` 后，再按“门店 + SKU ID”去重统计。

当前两个门店的数据如下：

| 统计口径 | 数量 |
| --- | ---: |
| 原始表总行数 | 19,552 |
| 商品观察记录 | 19,243 |
| 类目记录 | 309 |
| 门店内去重 SPU | 14,813 |
| 门店内去重 SKU | 20,654 |
| SKU 原始观察次数 | 55,617 |

SKU 原始观察次数较多，是因为同一个商品可能同时出现在“全部”、营销入口和普通类目中。

## 三、表字段

| 字段 | 含义 | 使用说明 |
| --- | --- | --- |
| `id` | 自增主键 | 数据库内部唯一编号 |
| `store_snapshot_id` | 门店采集版本 | 标识某次门店采集的数据版本 |
| `channel_code` | 来源渠道 | 当前为 `meituan_h5` |
| `store_code` | 门店编码 | 系统内稳定的门店标识 |
| `store_name` | 门店名称 | 业务人员可直接识别的门店名 |
| `source_store_id` | 平台门店 ID | 美团侧的来源门店标识 |
| `record_type` | 记录类型 | `product` 表示商品，`category` 表示类目 |
| `source_spu_id` | 来源 SPU ID | 商品在来源平台的 SPU 标识 |
| `category_key` | 来源类目标识 | 用于按来源类目查询 |
| `collected_at` | 采集时间 | 原始数据实际采集时间，精确到毫秒 |
| `raw_data` | 完整原始数据 | 保存商品、SKU、价格、库存、促销等全部原始 JSON |
| `record_hash` | 原始记录哈希 | 用于防止同一条原始记录重复入库 |
| `created_at` | 入库时间 | 数据写入数据库的时间 |

## 四、商品详细数据位置

商品详细信息位于：

```text
raw_data.productRaw
```

常用原始字段示例：

| JSON 路径 | 含义 |
| --- | --- |
| `$.productRaw.id` | SPU ID |
| `$.productRaw.name` | 原始商品名称 |
| `$.productRaw.picture` | 商品图片 |
| `$.productRaw.description` | 商品描述 |
| `$.productRaw.min_price` | 商品最低展示价格 |
| `$.productRaw.unify_price` | 商品统一价格结构 |
| `$.productRaw.promotion_info` | 商品促销信息 |
| `$.productRaw.month_saled_content` | 月售文案 |
| `$.productRaw.skus` | 完整 SKU 数组 |

## 五、SKU 详细数据位置

SKU 信息位于：

```text
raw_data.productRaw.skus[]
```

每个 SKU 中通常包括：

| JSON 路径 | 含义 |
| --- | --- |
| `$.id` | SKU ID |
| `$.name` | SKU 商品名称 |
| `$.spec` | 规格名称 |
| `$.upccode` | 商品条码 |
| `$.price` | SKU 基础展示价格 |
| `$.origin_price` | 原价 |
| `$.stock` | 库存数量 |
| `$.status` | 在售状态 |
| `$.promotion` | 促销信息 |
| `$.unify_price` | 完整价格结构 |
| `$.unify_price.activity_info.activity_price` | 活动价格 |
| `$.unify_price.activity_info.quota_per_order` | 单次限购数量 |
| `$.unify_price.actual_price_info` | 页面返回的实际价格信息，可能为空 |

不同商品返回的字段可能不同，应以 `raw_data` 中的实际内容为准，不应因为当前业务暂时不用就删除原始字段。

## 六、真实商品示例

以下数据来自乐购达超市（景耀店）的实际原始记录：

| 项目 | 原始值 | 数据位置 |
| --- | --- | --- |
| 门店 | 乐购达超市（景耀店） | `store_name` |
| 类目 | 神价 | `$.category.name` |
| SPU ID | `21548328764` | `$.productRaw.id` |
| 商品名称 | 【6罐】可口可乐 可乐 330ml*6罐 碳酸饮料矮罐装（新老包装随机） | `$.productRaw.name` |
| SKU ID | `38312674835` | `$.productRaw.skus[0].id` |
| 规格 | 330ml*6罐 | `$.productRaw.skus[0].spec` |
| 商品条码 | `6954767410623` | `$.productRaw.skus[0].upccode` |
| SKU 基础展示价 | 19.8 元 | `$.productRaw.skus[0].price` |
| 原价 | 19.8 元 | `$.productRaw.skus[0].origin_price` |
| 活动价 | 9.9 元 | `$.productRaw.skus[0].unify_price.activity_info.activity_price` |
| 单次限购 | 1 件 | `$.productRaw.skus[0].unify_price.activity_info.quota_per_order` |
| 库存 | 114 件 | `$.productRaw.skus[0].stock` |

这说明原始表中的一条商品记录不仅保存商品名称，还完整保存了 SKU、规格、条码、库存以及多种价格结构。

其中 19.8 元是 SKU 基础展示价，9.9 元是来源数据返回的活动价。活动价是否等于某个用户最终可支付的价格，还要结合活动资格、限购条件和页面展示语义判断，不能直接改名为“用户到手价”。

查询该商品的示例：

```sql
SELECT
  store_name,
  raw_data->>'$.category.name' AS category_name,
  raw_data->>'$.productRaw.name' AS product_name,
  raw_data->>'$.productRaw.skus[0].id' AS sku_id,
  raw_data->>'$.productRaw.skus[0].spec' AS spec_name,
  raw_data->>'$.productRaw.skus[0].price' AS display_price,
  raw_data->>'$.productRaw.skus[0].unify_price.activity_info.activity_price'
    AS activity_price,
  raw_data->>'$.productRaw.skus[0].stock' AS stock
FROM fact_store_raw_data_snapshot
WHERE store_code = 'legouda-jingyao-20260709'
  AND source_spu_id = '21548328764'
  AND record_type = 'product';
```

## 七、常用查询

### 查询商品原始信息

```sql
SELECT
  store_name,
  raw_data->>'$.category.name' AS category_name,
  raw_data->>'$.productRaw.id' AS spu_id,
  raw_data->>'$.productRaw.name' AS product_name,
  raw_data->>'$.productRaw.min_price' AS min_price,
  collected_at
FROM fact_store_raw_data_snapshot
WHERE record_type = 'product';
```

### 展开并查询 SKU

```sql
SELECT
  r.store_name,
  r.source_spu_id,
  r.raw_data->>'$.productRaw.name' AS product_name,
  sku.sku_id,
  sku.spec_name,
  sku.price,
  sku.stock
FROM fact_store_raw_data_snapshot r
CROSS JOIN JSON_TABLE(
  r.raw_data,
  '$.productRaw.skus[*]' COLUMNS (
    sku_id VARCHAR(128) PATH '$.id',
    spec_name VARCHAR(255) PATH '$.spec',
    price DECIMAL(18,4) PATH '$.price',
    stock DECIMAL(18,4) PATH '$.stock'
  )
) sku
WHERE r.record_type = 'product';
```

统计有效 SKU 时，还需要按照“门店 + SKU ID”去重，避免同一 SKU 在多个类目中重复计算。

## 八、使用原则

1. 本表是原始数据源，不直接承担商品比价计算。
2. 商品名称以 `raw_data.productRaw.name` 为准，不得修改原文。
3. SKU 数量必须展开 `skus[]` 后统计，不能直接使用原始表行数。
4. 同一商品在不同类目出现时，原始观察可以保留；业务结果再进行去重。
5. 页面价格、活动价格和实际到手价必须分别识别，不能将任意价格字段直接当作用户到手价。
6. SPU/SKU 业务表出现字段遗漏时，应以本表的完整原始数据重新生成。
