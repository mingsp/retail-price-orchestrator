## 4. 现场操作顺序

1. 业务同事通过 RDP 连接 66，在五个 Profile 中登录真实账号。
2. 每个标识页先填写账号标识、归属人、目标门店，再由 Worker 心跳回传。
3. Master 只在五项绑定与门店 POI 预检均通过后创建 Canary。
4. Canary 只选择一个低风险小类目，验证 raw、checkpoint、结构化商品、质量和对象存储。
5. 人工触发或等待一次验证码事件，确认通知、远程定位、处理、恢复和断点续采。
6. Canary 通过后冻结全店类目与优惠范围，多账号按固定类目并行；空闲账号只接管未完成类目。
7. 交付前逐类目核对 raw 行数、SPU、嵌套 SKU、展示价、优惠字段、checksum 和 checkpoint，禁止以页面百分比判定完成。

## 5. 201 恢复命令

在 201 管理员 PowerShell 执行，禁止为此直接重启整机：

```powershell
Restart-Service sshd -Force
Get-Service sshd
Get-NetTCPConnection -LocalPort 22 -State Listen
```

恢复 SSH 后，Codex 先只读核对 201 的版本、容器、计划任务、备份策略和 Worker 清单，再准备候选，不覆盖现有运行目录。

## 6. 禁止误报

- 端口监听不等于服务可用。

- CDP 页面存在不等于门店预检通过。
- Worker 自报完成不等于类目 `completed_valid`。
- 有 Excel 不等于全店完整。
- 合成测试通过不等于真实验证码、403/418 和全店采集已通过。
