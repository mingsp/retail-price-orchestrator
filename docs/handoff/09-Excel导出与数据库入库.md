# Excel 导出与数据库入库

## 顺序

```text
原始采集
  -> 原始数据质量门
  -> 结构化投影
  -> Excel 导出
  -> 数据库 dry-run
  -> 明确确认
  -> commit
  -> 读回审计
```

采集过程中不边抓边改商品名称或按业务模板裁剪原始字段。

## Excel

当前常用多 Sheet 模板：

- 店铺信息
- 类目信息
- 优惠券信息
- 商品信息

商品 Sheet 面向业务同事，不展示 run ID、本机路径、Profile 路径和接口调试字段。商品名称保持原始值。

导出后验证：

- Sheet 数和名称。
- 行列数。
- 长 ID 不使用科学计数法。
- 商品价格覆盖。
- 公式错误。
- 每个 Sheet 的视觉预览。
- 文件 SHA-256。

历史导出脚本只能作为字段参考。正式导出应从已冻结原始数据生成。

## 原始数据入库

原始事实写入 `fact_store_raw_data_snapshot` 或当前数据库中等价的原始表。基本要求：

- 一行对应一条原始商品或类目观察。
- `raw_data` 保存完整 JSON。
- 保存门店、批次、渠道、类目、SPU 和采集时间等索引字段。
- 使用稳定 `record_hash`。
- 唯一键阻止重复执行写入。
- `raw_data` 不裁剪、不改写。

当前仓库入口：

```text
apps/master/src/repositories/raw-data-sync.ts
scripts/backfill-native-capture-pipeline.ts
```

## 业务投影

SPU/SKU 和价格快照是下游投影。字段变化时应从原始数据重建，不需要重新采集历史门店。

数据库只负责存储事实和投影，不在事实表中直接进行竞对商品匹配和价格比较。

## 写入安全

- 真实连接信息只保存在本地环境文件。
- 默认执行 dry-run。
- commit 需要显式参数和用户确认。
- 写后按批次、门店、原始行、SPU、SKU、哈希和重复数读回。
- 失败时保留原始 artifact，不使用 Excel 反向补原始表。

## 优惠券

优惠券信息可能来自活动类目元数据和商品动态标签。导出时应区分：

- 优惠券名称和 ID。
- 活动 ID。
- 满减门槛和额度。
- 有效期。
- 商品页优惠标签。

无法证明的优惠名称或到手价留空，不凭规则文本猜测。
