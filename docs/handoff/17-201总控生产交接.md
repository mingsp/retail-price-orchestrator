# 201 总控生产交接

## 1. 节点定位

201 是长期在线的 Retail-Radar Master 总控，不作为日常采集浏览器使用。它负责：

- Worker 登记、心跳、Browser Slot、账号/Profile/CDP/门店绑定。
- 门店批次、类目任务、租约、暂停、恢复和风险事件。
- PostgreSQL 控制面、Redis 实时事件、MinIO 原始资产和 Excel 产物。
- Prometheus、Alertmanager、钉钉通知、每日备份和每周隔离恢复。
- Master 侧 Codex 智能值守；SSH 只用于安装、升级和故障维护。

业务人员在 Worker 上登录账号、处理验证码并执行任务。开发人员维护平台和确定性采集器。201 不替业务人员保存手机号明文、身份证生日或登录凭据。

## 3. 不允许迁移的内容

部署、升级和 Codex 交接不得手工复制：

- Worker 历史 JSONL、截图、checkpoint、日志或 Excel。
- Chrome Profile、Cookie、登录态、手机号、验证码或账号凭据。
- PostgreSQL/MinIO 运行卷到业务 Worker。
- 旧实验目录和临时采集过程文件。

201 接收新数据只能走正式任务产物链：Worker 预签名上传、SHA-256、对象版本和数据库 artifact 记录。历史 JSONL 留在原设备或原 Master，不因部署而迁移。

## 4. 启动后只读检查

1. `/api/version` 必须返回固定版本和 commit。
2. `/ready` 的 PostgreSQL、Redis、object storage 全部为 `ok=true`。
3. 8 个容器存在且核心容器健康：Caddy、Dashboard、Master、PostgreSQL、Redis、MinIO、Prometheus、Alertmanager。
4. `RetailRadarStandaloneStart`、健康监控、钉钉台账 dry-run、每日备份、每周恢复任务已登记。
5. Worker 心跳和 Browser Slot 必须来源于实时 API；账号/CDP 未启动时允许显示人工处理或不可用，不得伪造就绪。
6. 钉钉机器人必须不是占位符，并完成一次受控 firing/resolved 演练。

## 5. 运行与升级门禁

- 活动任务不为 0 时禁止升级、切换 app 或变更 Browser Slot。
- 先做 PostgreSQL + MinIO 一致性备份，再做隔离恢复，最后准备候选。
- 候选必须在固定 Node 22.14.0、pnpm 11.21.0 下离线安装、测试、类型检查和脱敏验证。
- 激活必须在新版本目录完成；健康或版本身份不匹配时回滚，旧目录不得删除。
- Docker 基础镜像可离线导入，但镜像包不得包含数据库卷、MinIO 数据、JSONL 或 Profile。
