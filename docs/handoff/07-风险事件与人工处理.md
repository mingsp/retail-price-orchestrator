# 风险事件与人工处理

## 处理原则

风险处理目标不是自动绕过限制，而是及时停止错误请求、保留断点、准确定位账号和页面，并让人工完成必要操作。

本文件定义风险闭环的共同规则。403 分类、账号/Profile 更换、登录和恢复的逐步操作以
`14-账号风控Profile与登录操作手册.md` 为准。

## 风险矩阵

| 症状 | 系统动作 | 人工动作 | 恢复门禁 |
|---|---|---|---|
| 验证码/身份核验 | 暂停 Slot，截图，保存断点 | 完成验证 | 页面、账号、门店复检 |
| HTTP 418 | 停止重试，进入冷却 | 检查页面或验证 | 明确健康后恢复 |
| HTTP 403 | 停止该门店请求 | 检查账号/Profile/网络 | Canary 通过 |
| 授权码过期 | 退出失效验证页 | 重新进入业务页面 | 新授权状态有效 |
| 登录失效 | 暂停任务 | 重新登录 | 账号标识回传一致 |
| 商品不可见 | 账号和 Profile 风险 | 更换账号和新 Profile | 新资源预检通过 |
| 多账号同设备异常 | Worker/device risk | 检查网络、代理和设备 | 单账号 Canary 通过 |
| 门店不匹配 | 请求前阻断 | 打开正确门店 | `poi_id_str` 一致 |
| Worker 离线 | 停止 lease 推进 | 恢复设备 | 心跳和 spool 对账 |

## 风险事件字段

- 时间
- Worker 和 Browser Slot
- 脱敏账号、Profile 和 CDP
- 门店和类目
- 当前阶段
- 页面标题和错误类型
- 截图 artifact
- checkpoint 版本
- 推荐人工动作
- 处理状态和处理人

风险通知中不显示完整手机号、Cookie、URL 动态请求参数和本机路径。

## 钉钉通知

即时通知：

- 验证码或身份核验。
- 403/418。
- 登录失效。
- 商品不可见。
- Worker 离线导致任务停滞。

里程碑通知：

- 门店有效进度达到 50%。
- 门店质量门达到 100%。

不按请求、页面或商品逐条通知。

## 人工处理后

1. 不要求人工再口头重复描述所有步骤。
2. Worker 或 Codex 轮询页面状态应保持低频。
3. 页面恢复后重新确认账号和门店。
4. 先执行不发商品请求的预检。
5. 从 checkpoint 继续。

## 升级条件

以下情况升级为设备/IP 风险：

- 同设备多个独立账号在短时间内对相同类型门店异常。
- 不同新 Profile 表现一致。
- 主页普通门店可访问，但目标即时零售门店持续不可见。

升级后停止该 Worker 新任务，不通过快速换号继续试。

## 风险闭环状态

```text
open -> acknowledged -> manual_processing -> resolved
                              \-> quarantined
                              \-> escalated
```

- `resolved`：证据证明原资源已恢复，并通过只读预检和 Canary。
- `quarantined`：账号或 Profile 被隔离，任务已迁移到新资源。
- `escalated`：多个账号或 Profile 出现共同异常，升级为设备/IP/业务线问题。

关闭风险事件前必须填写处理人、处理动作、恢复证据、任务去向和是否需要 D+1 复检。
