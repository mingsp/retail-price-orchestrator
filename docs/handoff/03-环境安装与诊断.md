# 环境安装与诊断

## 基础要求

### Master

- Node.js 22+
- pnpm
- Docker Desktop 或 Docker Engine
- PostgreSQL、Redis、MinIO、Caddy
- 固定局域网地址或稳定主机名
- 足够的对象存储和备份空间

### Worker

- Node.js 22+
- Google Chrome
- 可见的登录用户桌面会话
- Worker Agent
- 独立的纯采集 Profile 根目录
- 可用的远程桌面方式

## 默认只读诊断

源码仓库：

```powershell
node handoff/scripts/doctor.mjs --json
```

发布包：

```powershell
node scripts/handoff/doctor.mjs --json
```

默认检查本机工具、磁盘、时间和配置结构，不连接 CDP、不启动 Chrome。

## Master 本地开发

```powershell
docker compose -f infra/docker-compose.yml up -d
pnpm dev:master
pnpm dev:dashboard
```

生产部署使用 `infra/docker-compose.production.yml` 和 `docs/handoff/10-部署升级回滚与备份.md`，不要把本地开发密码带入生产。

## Worker 接入

优先使用 `deploy/windows` 或 `deploy/macos` 安装器。SSH 只用于首次安装、升级和故障维护。

接入后核对：

- 系统中只有一个物理 Worker 记录。
- Worker ID 来自接入流程，不复制其他设备 identity。
- Chrome 运行在运营人员可见的桌面会话。
- Browser Slot 和远程桌面目标可定位。

## 网络

美团相关页面应按公司网络策略走合规稳定链路。代理规则是否生效必须通过当前页面定位和实际网络检查确认，不能仅凭浏览器显示地址推断。

## 诊断原则

- 先检查进程、端口和页面，再重启。
- 只终止本项目启动的进程。
- 不因单个 CDP 失败重启全部 Worker。
- 不在账号异常时连续新建 Profile 并快速重试。
- 所有环境变化记录时间、设备和回滚方式。
