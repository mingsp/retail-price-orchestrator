# 部署、升级、回滚与备份

## 生产方向

- 独立 7×24 小时 Master 主机。
- Worker 主动连接 Master。
- SSH 只用于安装、升级和故障维护。
- Codex 只部署在 Master 侧。
- Worker 不需要安装 Codex。

## Master

生产 Compose 包含：

- Caddy
- Master API
- Dashboard
- PostgreSQL
- Redis
- MinIO

入口使用 HTTPS/WSS。数据库、Redis 和 MinIO 管理端口不直接暴露给 Worker。

部署说明：

```text
project/docs/master-deployment.md
project/infra/docker-compose.production.yml
```

## Worker

### Windows

- WinSW 运行核心 Worker 服务。
- 登录用户会话中的计划任务运行可见 Chrome/CDP Helper。
- 不从 Session 0 直接启动需要人工处理的 Chrome。

### macOS

- 用户级 `launchd` LaunchAgent。
- Chrome 保持在当前登录用户桌面。
- 使用 `caffeinate` 或系统电源策略防止长任务休眠。

## 发布升级

1. 构建 Worker 发布包。
2. 生成 SHA-256 和 Ed25519 签名 Manifest。
3. 选择一台 Canary Worker。
4. Worker 进入 drain，不领取新任务。
5. 当前任务到安全断点。
6. 安装新版本并检查稳定在线窗口。
7. 失败时恢复上一不可变版本目录。
8. Canary 通过后分批升级。

Master 升级也遵循同一原则：固定 Tag、版本化源码目录、活动任务为 0、PostgreSQL/MinIO 联合备份、单节点 Canary、稳定窗口、第二节点切换。不得在当前运行目录覆盖式 `git pull`，不得同时切换两个 Master 节点。

## 回滚

回滚只切换活动版本，不删除：

- Worker identity。
- 本地 spool。
- Profile。
- checkpoint。
- 未上传 artifact。

## 备份

- PostgreSQL 每日逻辑备份。
- MinIO 使用对象版本和生命周期策略。
- Master 配置与签名公钥备份。
- 密钥备份放在独立秘密管理位置。
- Worker 本地原始文件在 Master 校验前不得删除。

## 故障演练

上线后必须现场验证：

- Master 重启。
- Redis 短时不可用。
- Worker 断网和恢复。
- Chrome 意外退出。
- Worker 设备重启。
- 跨 Worker checkpoint 迁移。
- 验证码截图和远程桌面定位。
- Worker Canary 升级失败回滚。

## 生产备份门禁

`deploy/windows/backup-master.ps1` 只允许在活动任务数为 0 时执行，并同时生成：

- PostgreSQL 自包含格式 dump、目录校验和关键表行数；
- MinIO 完整版本化数据卷 tar 和 SHA-256；
- 当前容器镜像 ID、配置文件哈希和备份清单。

`deploy/windows/restore-drill.ps1` 只恢复到随机命名的隔离数据库与临时 Docker 卷，逐表核对行数、逐卷核对对象文件数，记录 RPO/RTO 后清理隔离资源。任何 checksum、行数或对象目录不一致都必须阻断升级。

从旧版本升级时，备份工具必须兼容旧库中尚不存在的新表。若预检报告 `scope_manifests` 等新表不存在，保持生产不切换，使用经过审阅的旧库兼容备份流程完成 PostgreSQL/MinIO 备份并记录哈希；不得为了让备份脚本通过而提前创建新表。

非交互 SSH 构建必须显式使用发布验证过的 Node 22 运行时和 CI 模式。Docker Desktop 凭据会话不可用时，优先使用已验签、内嵌版本信息一致的本地候选镜像；不得跳过镜像身份核对或临时改用 `latest`。

历史本机 E2E 不能替代真实设备演练。
