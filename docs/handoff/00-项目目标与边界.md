# 项目目标与边界

## 业务目标

从指定即时零售门店取得用户在 H5 页面看到的商品、SKU、价格、活动和类目信息，完整保存原始数据，再由下游进行商品匹配和比价。

本系统首先是 Master-Worker 调度和数据生产系统，不是单机爬虫脚本。

## 必须解决的问题

- 多设备、多个账号和多个纯采集 Profile 的稳定管理。
- 一个账号负责固定门店和固定类目，避免重复领取。
- 低频、可暂停、可恢复的原始数据采集。
- 验证码、登录失效、403、418 和商品不可见的人工闭环。
- Worker 离线、Master 重启和跨 Worker 迁移时不丢断点。
- 原始 SPU、嵌套 SKU、展示价和商品名称可追溯。
- 产物可以导出 Excel，也可以按原始事实入库。

## 不做什么

- 不绕过验证码或身份核验。
- 不以代理池、账号轮换或指纹伪装规避平台限制。
- 不保存账号密码或 Cookie 到 Master。
- 不把商家后台价格替代用户前端展示价格。
- 不在原始采集阶段做业务商品匹配和比价。
- 不允许以进程退出或单一百分比宣告全店完整。

## 当前规模与扩展方向

系统按 10 台 Worker、30 个 Browser Slot、20 个门店的扩展目标设计。当前具体设备、账号、IP、CDP 端口和门店由现场配置决定，交接文档不保存易变映射。

## 权威边界

事实优先级：

1. 当前页面、当前环境和当前运行证据。
2. 当前源码和测试。
3. 当前发布记录和 `docs/handoff/`。
4. 历史验证报告。
5. 旧实验脚本和旧会话。

历史上成功过的端口、账号和请求参数不得直接复用，必须重新现场验证。
