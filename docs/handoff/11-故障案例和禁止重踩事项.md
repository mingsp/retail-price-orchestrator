# 故障案例和禁止重踩事项

## 1. 固定每页 20 条

**问题：** 请求次数过多，容易触发异常。  
**结论：** 服务端和页面方法不应被假定为固定 20 条。优先缓存、完整 ID 集和动态缺失补齐。

## 2. 新账号直接打旧深页

**问题：** 新 Profile 首次请求就出现 418 或验证。  
**结论：** 新账号自然进入门店，从类目入口开始，不复用旧 UUID、访问参数和深页游标。

## 3. 风险 Profile 换新账号

**问题：** 新账号刚登录就异常。  
**结论：** 风险账号与 Profile 一起隔离，新账号使用新的纯采集 Profile。

## 4. Profile 登录商家后台

**问题：** 消费者 H5 账号更容易出现门店不可见或 403。  
**结论：** 纯采集 Profile 不登录商家端和无关系统。

## 5. 全局海外代理

**问题：** 页面定位或网络出口与目标门店区域明显不一致。  
**结论：** 按合规网络策略让相关域名走稳定链路，并现场验证；不要关闭维持 Codex 所需的网络后导致控制会话中断。

## 6. 验证后等待人工再次通知

**问题：** 人工处理完成后任务长时间不恢复。  
**结论：** Worker 对风险页面做低频状态检查；恢复后自动执行页面和门店预检。

## 7. 一个账号重复采同一类目

**问题：** 请求浪费并增加风险。  
**结论：** 固定类目分工，领取和写入使用 lease/fencing。

## 8. Worker/账号/门店混淆

**问题：** 本机账号采到另一个 Worker 原计划门店。  
**结论：** 调度以 Browser Slot 绑定为准，不靠端口、窗口顺序和人工记忆。

## 9. 离线 CDP 不重启或盲目重启全部

**问题：** 单 Slot 故障拖累其他任务，或重启造成登录丢失。  
**结论：** 只诊断和恢复目标 Slot，只终止本项目启动的进程。

## 10. progress 显示完成但无原始类目标记

**问题：** 类目被错误报告完成，实际 raw 写入为 0。  
**结论：** 完成必须有独立 raw 类目标记、商品证据和质量门，不能只信 progress。

## 11. 用类目关系数冒充唯一 SKU

**问题：** 同商品跨类目重复，系统显示虚高。  
**结论：** 同时报告门店唯一 SPU/SKU 与类目-商品关系。

## 12. 只看最后一次 SPU 快照

**问题：** 旧 SKU 或缺货 SKU 被漏掉。  
**结论：** 对账完整原始证据并集，包括所有嵌套 SKU 和独立 SKU 记录。

## 13. 把展示价等同到手价

**问题：** 用户到手价覆盖很低，直接比较会误判。  
**结论：** 前端展示价、原价、活动价和到手价分别保存；没有完整条件不计算虚假到手价。

## 14. 采集时同步清洗

**问题：** 原始字段被裁剪，后续字段需求变化无法补回。  
**结论：** 原始数据先完整保存，清洗、Excel 和业务表最后生成。

## 15. 直接压缩整个工作区

**问题：** Profile、Cookie、runtime、密钥和 10GB 过程文件被交接。  
**结论：** 使用交接构建器的白名单快照和二次敏感扫描。

## 16. 历史验证冒充当前生产

**问题：** 旧报告写着通过，但新设备、账号或当前代码未验证。  
**结论：** 使用 L0～L4 验证层级，现场事实必须重新确认。
