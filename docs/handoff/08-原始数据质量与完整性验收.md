# 原始数据质量与完整性验收

## 两个商品口径

必须同时报告：

1. **门店唯一商品**：按门店 + SPU 或 SKU 去重，用于判断门店实际商品规模。
2. **类目-商品关系**：同一商品出现在多个类目时分别保留，用于核对每个类目是否采全。

两者不能相加，也不能用类目关系数冒充门店唯一 SKU。

## 原始事实

每条商品观察至少保留：

- 采集时间。
- 门店、批次、任务和类目。
- Worker、账号、Profile 和 CDP 的脱敏标识。
- `productRaw` 完整对象。
- `productRaw.skus[]`。
- 页面提取的 `productIndex`。
- 展示价及其来源。

原始商品名称不允许清洗、纠错、截断或改写。

## SKU 对账

SKU 完整证据是以下并集去重：

- 所有 `productRaw.skus[]`。
- 独立 SKU 原始记录。
- 页面索引中的 SKU。

不能只读取某个 SPU 的最后一次快照。旧快照或缺货 SKU 可能只存在于其他原始记录中。

## 价格字段

主要业务口径是用户 H5 页面展示价。常见优先级：

```text
unify_price.activity_info.activity_price
  -> frontDisplayPrice
  -> min_price
  -> sku.price
  -> unify_price.price
```

每个投影价格必须保留原始来源路径。`0.01`、首件价、限量价等吸引用户的价格不能因看起来异常而自动替换。

到手价、券后价和前端展示价不是同一个概念。没有完整优惠条件时，不得把估算值写成事实。

## 类目验收

对每个计划类目核对：

- 类目标记和名称。
- 期望 SPU 或 `allSortedSpuId`。
- 实际原始 SPU。
- 缺失 ID。
- checkpoint 完成状态。
- raw artifact。
- 请求和风险摘要。

旧 progress 的 `completed=true` 如果没有独立 raw 类目标记，不算有效完成。

## artifact 验收

- 文件存在且非空。
- JSONL 每行可解析。
- 大小与登记一致。
- SHA-256 与登记一致。
- 对象存储读取的是冻结时的精确版本。
- 晚到同 key 新版本不能改变已冻结交付。

## 交付质量门

完成至少要求：

- 所有有效类目有原始证据。
- 可解释缺口单独列出。
- 嵌套 SKU 与结构化 SKU 对账。
- 商品名称一致。
- 展示价覆盖达到业务要求。
- 无错误门店、错误账号和重复执行行。
- 原始数据可重新生成当前投影。

质量门未通过时状态保持 `captured/validating/partial`，不能标记 `completed_valid`。
